# 测试与验收

公开仓库中的自动化测试使用虚构的档案、测量数值和日期。测试创建的数据库位于临时目录或被忽略的 `.qa` 目录，不需要真实用户截图，也不应操作日常使用的 `data` 目录。

在项目根目录运行：

```powershell
python -m unittest test_analysis test_ocr test_server -v
node --test test_chart.cjs
```

覆盖范围：

- 数据保存：SQLite 新增、编辑、删除、重复检测、导入回滚、ZIP 备份恢复和访问限制。
- 建议规则：缺少档案或健康确认、年龄边界、BMI 与设备资料不一致、恢复不足、稀疏记录、异常值和过期测量；不从少量记录推断长期效果。
- OCR 解析：中英文标签、两列坐标、正负数与小数、当前日期和历史比较的区分、数值缺失、歧义与超时。解析测试使用合成文字与坐标，并检查更换数值后结果随输入变化。
- 趋势图：上海时区、日历时间窗口、缺失值、同日多次测量、设备比较推算点、空态和可访问 SVG 渲染。

## 可选的本机 OCR 验证

Windows OCR 的可用性和识别效果取决于本机系统、语言包及图片质量。默认测试会跳过需要图片的本机引擎检查；核心解析测试仍会运行。

需要验证本机引擎时，在仓库外保存自己的截图和一个 JSON 清单。下面的数值仅为格式示例，应替换成所选图片中人工核对的期望结果：

```json
{
  "image": "report.png",
  "expected": {
    "weight": 75,
    "body_fat": 20.1
  }
}
```

`image` 相对清单所在文件夹解析。随后在 PowerShell 中指定清单路径：

```powershell
$env:BODY_JOURNAL_OCR_FIXTURE = "C:\private-test-fixtures\ocr-manifest.json"
python -m unittest test_ocr.LocalEngineTests -v
```

图片和清单无需加入 Git。这个检查只断言清单中列出的字段；应按实际图片填写期望值，不能据此宣称所有图片都有相同识别率。无法可靠识别的项目应留空，在保存前由使用者核对。

## 界面与发布前检查

使用独立测试数据目录启动程序，检查上传核对、手动新增与编辑、页面刷新后的保存状态、图表切换、个人档案更新后的建议、每日任务和训练日志、备份合并、重复与冲突提示。再检查桌面与窄屏布局、启动与停止入口以及重启后的持久化状态。

发布的仓库和下载包应为空白个人档案，不包含数据库、日志、原始体测图片、私有测试清单或显示个人资料的验收截图。本机建议来自规则计算，OCR 使用 Windows 内置引擎；这些测试不代表医学诊断或长期效果验证。
